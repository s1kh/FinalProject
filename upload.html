Unrestricted File Upload

What it is

A site lets users upload images, but it only checks the file extension. An attacker uploads a dangerous file with a harmless name. If the server stores it and runs it, the attacker controls the server.

OWASP: A04:2021 Insecure Design. CWE-434.

The line

function upload(file) {
  // Only allow JPEG images
  const name = file.name.toLowerCase();

  if (name.endsWith(".jpg")) {
    save(file);
    return "Uploaded";
  }

  return "Rejected";
}

The check trusts the file extension. The attacker chooses the extension, so the check means nothing.

Try it

No real upload happens. The files are fake and made in your browser.

Why it matters

An uploaded script can give the attacker full control of the server: read data, change pages, attack other users.

Real incident: in 2020, the WordPress plugin WP File Manager (CVE-2020-25213) let anyone upload files without logging in. Attackers used it to upload malicious PHP files and run code on the site's server. It was actively exploited in the wild.

The fix

async function upload(file) {
  const head = new Uint8Array(
    await file.slice(0, 3).arrayBuffer());

  const isJpeg = head[0] === 0xFF && head[1] === 0xD8 && head[2] === 0xFF;

  if (isJpeg && file.size < 1000000) {
    save(file);
    return "Uploaded";
  }
  return "Rejected";
}

Now the check reads the real bytes. Every JPEG starts with FF D8 FF. The same payload (shell.php.jpg) is rejected.

Test the fix:

On a real server, also rename the file randomly, store it outside the web root, and never run uploaded files.
