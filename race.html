Race Condition

What it is

A race condition happens when two requests run at the same time and the result depends on who finishes first. The app checks a value, then changes it later. In between, another request sneaks in.

OWASP: A04:2021 Insecure Design. CWE-362.

The line

let balance = 100;

async function withdraw(amount) {
  if (balance >= amount) {
    await sleep(100); // database delay
    balance -= amount;
    return "OK";
  }
  return "Rejected";
}

The check and the update are two separate steps. During the delay, a second request passes the same check before the first one updates the balance.

Try it

The account starts with 100. Every request tries to withdraw 100. Each button starts from a fresh balance. No real money, only a simulation.

Why it matters

Attackers send many requests at the same moment to spend a coupon twice, withdraw more than they own, or redeem a gift card again and again. The code looks correct when you read it. The bug only appears under timing.

Real incident: Dirty COW (CVE-2016-5195), a race condition in the Linux kernel that allowed attackers to gain root access.

The fix

let locked = false;

async function withdraw(amount) {
  while (locked) await sleep(10);
  locked = true;
  try {
    if (balance >= amount) {
      await sleep(100);
      balance -= amount;
      return "OK";
    }
    return "Rejected";
  } finally {
    locked = false;
  }
}

Now only one request can work at a time. The others wait. The same payload (2 requests at once) is blocked: the second request is rejected. In a real database, use a transaction or an atomic update instead.
