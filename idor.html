IDOR

What it is

IDOR means Insecure Direct Object Reference. The app shows data by an ID in the request, but never checks that the data belongs to you. Change the ID, and you read someone else's data.

OWASP: A01:2021 Broken Access Control. CWE-639.

The line

const invoices = {
  1001: { owner: "alice", total: "$50" },
  1002: { owner: "bob",   total: "$75" },
  1003: { owner: "carol", total: "$120" }
};

function getInvoice(id) {
  const inv = invoices[id];
  return inv;
}

The function only receives the id. It finds the invoice and returns it. It never asks: who is the user, and does this invoice belong to them?

Try it

You are logged in as alice (fake user).

/invoice?id=...
Press a button.

Why it matters

An attacker can read thousands of private records by counting up the IDs. No hacking tools are needed, only a browser. This can leak invoices, messages, medical files, and addresses.

Real incident: Optus (Australia, 2022). Customer data was exposed through an API with predictable IDs.

The fix

function getInvoice(id, currentUser) {
  const inv = invoices[id];
  if (!inv || inv.owner !== currentUser) return null;
  return inv;
}

Now the function also receives the user, and checks the owner. The same payload (id=1002) is blocked.
